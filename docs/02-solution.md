# 02 · 技术方案（初赛范围）

> 本文合并自：05 竞品定位、09 设计决策、12 技术纵深、13 兼容性评估。
> **只写初赛要做与要讲的内容。** 未标注"储备"的，都是初赛必须完成或必须讲清。

---

## 1. 一句话方案

在插座/配电回路侧用 PZEM-004T 采集电压、电流、功率、功率因数，提取负载形态特征，用轻量模型在**端侧**判断是否存在"越界用电"（违规充电 / 大功率电器），**断网也能告警**；有网时把误报与未知样本上传华为云，**批量复盘并迭代模型后下发**。

---

## 2. 数据采集

### 2.1 采集对象与规格

| 负载 | 标签 | 单段时长 | 段数 | 备注 |
| --- | --- | --- | --- | --- |
| 电瓶车充电器 | `e_bike_charger` | 60–180 min（覆盖完整平台期） | ≥20 | 最重要，尽量多型号 |
| 电热水壶 | `kettle` | 8–10 min | ≥20 | 完整"高功率→归零" |
| 吹风机 | `hair_dryer` | 8–12 min | ≥20 | 换档位制造跳变 |
| 正常/待机 | `normal` | 20–60 min | ≥20 | 小功率设备组合 |
| **混合负载** | `mix_*` | 10–30 min | **10–15** | 两个电器同时运行（单元级验证用） |

**采样**：1 Hz（PZEM 原生），每段自动生成 `.meta.json`（时长、间隔、峰值、采集人）。

### 2.2 采集规范（决赛复现的前提）

- 文件名由程序生成（时间戳），**不手动改名**
- `data/README.md` 记录：日期、环境温度、插座位置、设备型号、采集人
- 原始数据**只留本地**（已 `.gitignore`），仓库只提交特征表与指标
- 采集前告知参与者用途；不采与比赛无关的信息

### 2.3 同步录音（路径 A 用，可选）

若做声电双模：音频与 CSV **同名**存放，手机固定位置同步录，采样率 ≥16 kHz。

## 3. 特征工程

### 3.1 电气特征（已实现于 `src/analyze.py`）

| 类别 | 特征 |
| --- | --- |
| 功率水平 | mean / std / max / min / p95 / p05 |
| 形态 | 平台度（接近中位数的样本占比）、阶跃比（最大正向跳变/峰值） |
| 波动 | 变异系数 CV、高功率占比、最长连续高功率时长 |
| 电气质量 | 功率因数均值/标准差、电压均值 |

**设计依据**：充电器"阶跃→长平台→缓降"平台度高；水壶"突升→突降"；吹风机方差大；正常负载功率低且稳。

### 3.2 音频特征（路径 A，可选）

MFCC（前 13 维统计量）、频谱质心、过零率、高频能量占比（3–8 kHz）。

## 4. 模型与实验设计

### 4.1 基线模型

标准化 + 随机森林（`src/train.py`），支持**留一交叉验证**（样本少时最诚实）。

### 4.2 两个必做的实验（这是"技术含量"所在）

**实验 B：少样本 + 未知设备泛化（必做）**

| 设置 | 说明 |
| --- | --- |
| 训练 | 每类只用 3–5 个样本 |
| 测试 | 含**训练时完全没见过的电器** |
| 指标 | few-shot 准确率、**未知设备拒识率**、未知设备误分类率、开集 F1 |

**意义**：开集识别是 NILM 领域公认难题；**且是云端迭代闭环的输入**——端侧知道自己"不认识什么"，云端才知道该学什么。

**实验 A：声电双模融合（可选）**

| 设置 | 说明 |
| --- | --- |
| 对照 | 仅电气 / 仅音频 / 融合 |
| 指标 | 三者准确率、**融合增益**、加背景噪声后的退化幅度 |
| 难点 | 时间对齐（采样率差 2–3 个数量级）、噪声抑制、模态互补性分析 |

### 4.3 混合负载实验（单元级的关键验证）

单负载只能证明"能分类"，**混合负载才能证明"一个点位覆盖一个单元"**。

| 设置 | 说明 |
| --- | --- |
| 数据 | 充电器+水壶、充电器+吹风机、充电器+正常、水壶+吹风机 等 10–15 段 |
| 目标 | 在多电器叠加的总功率里，检出"充电器是否在运行" |
| 指标 | 混合场景**检出率**、混合场景**误报率**、相对单负载的**下降幅度** |
| 诚实处理 | 若下降明显，如实报告并写明改进方向（提高采样率/换更强特征） |

> 详见 [`10-unit-level-monitoring.md`](10-unit-level-monitoring.md)。

### 4.3 不做

- 电池健康/类型判别（样本风险高，仅写"未来工作"）
- 极限压缩与 MCU 实测（初赛无板子）

## 5. 云端迭代机制（初赛**讲清即可，不实现**）

### 5.1 闭环

```
端侧：判断 → 产生「误报」与「未知设备」两类样本
   │ 有网时上传（仅上传特征 + 判断结果，不上传原始波形）
   ▼
华为云：RDS 积累样本 → 批量复盘 → 重训 → Redis 存版本指针 → 下发新模型
   ▼
端侧：热更新模型（失败则回退到上一版本）
```

### 5.2 云服务怎么用（对应赛题要求）

| 服务 | 在方案里的角色 |
| --- | --- |
| **CodeArts 码道** | 开发工具（必选）：生成采集/分析/推理代码与部署脚本 |
| **Skills** | 一键开通 RDS / Redis、一键部署（总决赛演示时用） |
| **RDS** | 存样本、模型版本、设备注册 |
| **Redis** | 模型版本指针、实时阈值缓存 |
| **MaaS** | 复盘时的辅助分析（如对未知样本聚类命名） |
| **OBS** | 模型文件与日志归档 |

> **初赛材料里画成这样一张图 + 写清机制即可**，不需要真的部署。

### 5.3 离线降级策略（必须写明）

- 无网时：继续使用现行模型，本地告警不受影响
- 更新失败：回退上一版本
- 长期无网：模型不退化，只是不再进化

## 6. 指标台账（初赛材料第 5 项）

### 6.1 必报指标

| 指标 | 定义 | 目标 |
| --- | --- | --- |
| 验证方式 | 留一交叉验证 / 留出法 | 必须写明 |
| 样本数 | 真实采集段数（**不含合成**） | ≥80 |
| 分类准确率 | 未见样本 | ≥85% |
| 充电类召回率 | 漏报率 = 1 − 召回 | 尽量高 |
| 非充电类误报率 | 误报会打扰用户，必须报 | 尽量低 |
| **未知设备拒识率** | 正确说"不认识"的比例 | 实验 B 产出 |
| 端侧推理耗时 | 笔记本 CPU ms 级 | 记录 |
| 断网可用 | 拔网线后仍能判断 | 是 |

### 6.2 可选指标（做了路径 A 才报）

单模准确率、融合准确率、**融合增益**、噪声下退化幅度。

### 6.3 诚实原则

> 宁可写 85%，不要写 99%。**总决赛会按材料复现，写高了直接取消资格。**
> 合成数据只能用于流程验证，**不得作为实验指标来源**。

## 8. 技术风险与对策

| 风险 | 概率 | 对策 |
| --- | --- | --- |
| 某类数据采不够 | 中 | 优先保证充电器 + 正常；退化为二分类保底 |
| 准确率上不去 | 中 | 换特征（加功率因数序列）、换模型（GBDT）、缩类别 |
| 借不到电瓶车充电器 | 中 | 先用大功率电器 + 公开数据集（PLAID/UK-DALE 等）跑通 |
| 未知设备样本凑不齐 | 低 | 多借几个小电器；或用留一类（leave-one-class-out）模拟 |
| 音频对齐做不好 | 中高 | 退化为仅电气单模，不硬上路径 A |
