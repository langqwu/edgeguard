# 04 · 创新性到底怎么评？竞品调研 + 往年获奖复盘 + 新方向建议

> 文档定位：回答三个问题——①赛题要求的"创新性"到底有多新？②我们要做的方向市面上有没有成熟产品？③往年拿一等奖的作品是什么水平？
> 结论先行：**竞赛对创新的真实要求 = "在一个具体缝隙上做出可量化、可复现的技术突破"，不是"发明新品类"，也不是"创新商业模式"。**

---

## 一、先说结论（三句话）

1. **"市面上有没有同类产品"不是否决项，而是"差异化论证的起点"**——赛题原文只要求"与行业现有方案做出差异化优势"。但差异化必须**可被评委验证**，不能是嘴上说的。
2. **真正的分水岭在"技术纵深 + 可量化指标"**。往年一等奖全部是"在某个具体缝隙上，用华为技术栈做出了过去做不到的效果"，并且**有数字、能复现、已开源**。
3. 因此判断一个方向能不能打，看四件事：**缝隙够不够具体 / 华为栈用得够不够深 / 指标能不能测 / 复现难度高不高**。任何一条不满足，创新性 60% 就会失分。

### 3.1 从五个案例里提炼出的"获奖公式"

```
真实且具体的痛点（越具体越好，最好是"盲区/缝隙/基层/离线"这类词）
        ×
华为技术栈的 2–4 个真实组合（昇腾系 + 通信/端侧系）
        ×
一个"过去做不到"的量化突破（时延 / 准确率 / 预警提前量 / 成本）
        ×
可复现（开源 + 文档 + 数据集说明）
```

### 3.2 反面清单（评委已经看过太多，不要碰）

- ❌ 自然语言生成应用 / 智能体搭建平台（大厂全覆盖）
- ❌ 通用聊天助手、知识库问答（除非有专业微调 + 硬指标）
- ❌ 大屏可视化 / 数字孪生"炫技"（无真实业务流，复现必挂）
- ❌ 纯商业模式创新（"我们换了个收费方式"——不是技术创新）
- ❌ 纯交互创新（"我们改成了语音"——功能层）

## 四、赛题对"创新性"的真实口径（官方原文 + 解读）

### 4.1 官方怎么写的

- 创新性（初赛 60%）："AI 应用场景的**创新**（发掘新场景或传统场景新突破）；与行业现有方案做出**差异化优势**等。"
- 应用价值（初赛 40%）："精准定位真实需求并解决对应问题；方案具备商用落地潜力，具备可复制性及规模化应用前景；技术架构完备，且具有可行性；**能证明呈现结果的有效性和严谨性**。"

### 4.2 解读：三个"不必"和三个"必须"

| 三个"不必" | 三个"必须" |
| --- | --- |
| 不必是全球首创 | 必须是**具体缝隙**，不能是泛泛场景 |
| 不必绕开所有竞品 | 必须能**说清与竞品的差异**，且差异可验证 |
| 不必发明新商业模式 | 必须有**可量化指标**，且决赛能复现 |

### 4.3 竞争线的真实位置

- **及格线**：新场景 + 用了华为栈 + 有 Demo
- **获奖线（二三等奖）**：明确的缝隙 + 2 个以上华为栈 + 有指标
- **一等奖线**：缝隙足够"难" + 技术纵深（端侧/推理/多模态/算法自研）+ 指标硬 + 已开源（+论文/软著）

**我们作为 3 人本科生队，现实目标是先站稳"获奖线"。** 技术纵深不一定要做算法创新，可以是**工程纵深**：端侧部署、离线可用、多模态融合、成本压到 1/10。

## 五、按新标准重新设计的 4 个方向

> 每个方向都按"缝隙 / 华为栈 / 量化指标 / 竞品差异 / 风险"五栏给出。全部避开"生成应用"和"通用助手"。

### 方向 1｜断电可用的端侧 AI 助手（技术纵深最高）

- **缝隙**：林区、渔船、矿井、边远卫生院、地下车间——**没有网络，但需要 AI**。云端大模型在这些地方直接失效。
- **产品形态**：一个"AI 边缘盒子"（昇腾/瑞芯微开发板 + 鸿蒙），本地跑量化后的小模型 + 行业知识库；断网可用、数据不出厂、毫秒级响应；有网时与云端同步、更新知识。
- **华为栈**：昇腾 Atlas 200I DK / 昇腾云、MindSpore Lite（量化+端侧推理）、鸿蒙分布式、星闪（本地组网）、云端 RDS/Redis 做知识同步。
- **可量化指标**：模型压缩比、首字延迟（对比云端 API）、离线准确率（对比在线）、断网可用时长、单设备成本。
- **竞品差异**：云端助手（通义/文心/盘古 API）假设有网；我们做的是"**把 AI 搬进没有网的地方**"，差异是场景级的，且能用"断网演示"一击证明。
- **风险**：端侧部署学习曲线陡（但有 CodeArts 辅助）；需要一块昇腾开发板（预算内）。**这是我最推荐的方向。**

### 方向 2｜从"事后看清"到"事前预测"：电气火灾隐患预警（最务实）

- **缝隙**：现有产品（摄像头、烟感）都是**事后**发现；电瓶车充电起火、线路老化、违规大功率电器的真正前兆在**电学信号**里，而摄像头看不见、烟感来不及。
- **产品形态**：智能插座级采集模块（电流/电压波形）+ 端侧轻量模型识别"电瓶车电池充电 / 热得快 / 线路异常" + 云端台账与推送；**不依赖摄像头**（隐私友好，这是天然卖点）。
- **华为栈**：端侧推理（昇腾或 MCU + MindSpore Lite）、IoTDA 接入、鸿蒙告警端、RDS 存波形与台账、Redis 做实时阈值。
- **可量化指标**：波形识别准确率、**预警提前量（分钟级 vs 事后）**、误报率、单点改造成本。
- **竞品差异**：市面多是"电瓶车进电梯识别"（视觉，事后、且只覆盖电梯），我们是"**用电行为的前兆识别**"，覆盖楼道、宿舍、出租屋，且不需要摄像头。
- **风险**：真实波形数据采集需要电机/电池等负载（找实验室或维修店借）；需要诚实标注数据来源。

### 方向 3｜AI 不确定时会"辞职"：现场作业的人机接力（产品机制最独特）

- **缝隙**：现场作业（设备维修、巡检、护理）里 AI 最大的问题不是不准，而是**不准的时候没人管**，导致用户不敢用。
- **产品形态**：现场端（手机/鸿蒙设备）AI 识别 → 给出结论并标注**置信度** → 置信度低时**主动发起远程专家接力**（一键呼叫、共享现场画面、专家标注直接变成可执行指令）→ 全过程沉淀为可复用的作业知识。
- **华为栈**：鸿蒙端、星闪（现场设备互联）、MaaS/盘古（多模态识别）、RDS/Redis（作业与知识沉淀）、CodeArts（生成全链路）。
- **可量化指标**：AI 自动解决率、专家接力耗时、**二次返工率下降**、知识复用率。
- **竞品差异**：现有 AI 助手都在优化"答对率"；我们优化"**答错时怎么办**"——这是机制层创新，评委很少见。
- **风险**：需要设计可信的"置信度"（可用模型自评 + 多模型投票）；演示里"专家"需要模拟，要设计得自然。

### 方向 4｜给老设备加一层"AI 预警层"（工业，纵深够但竞品多）

- **缝隙**：中小工厂的设备没有传感器、没有联网，停机损失大；换新设备不可能。
- **产品形态**：磁吸式振动/温度小模块（电池供电、星闪/蓝牙）→ 端侧异常判断 → 云端趋势分析与预警；**不换设备、不停产**改造。
- **华为栈**：星闪/鸿蒙、IoTDA、端侧模型、RDS/Redis、MaaS 做故障解释。
- **可量化指标**：预警提前量、误报率、单台改造成本、部署耗时。
- **竞品差异**：大厂做的是"新设备自带监测"；我们做"**存量设备零改造**"。
- **风险**：预测性维护是热门赛道，需要非常具体的缝隙（如"注塑机/空压机"单一机型）才能站住。

### 推荐组合

**主攻方向 2（电气火灾事前预警），把方向 1 的"端侧离线"作为技术亮点叠加。**

理由：
1. 方向 2 的缝隙极其具体（"事后 vs 事前"、"视觉 vs 电学信号"），评委一听就懂，且**能一击证明**——断网状态下，端侧模块仍能在起火前报警。
2. 指标硬且便宜可测：预警提前量、误报率、识别准确率，全部能用小规模实验测出来（决赛能复现）。
3. 华为栈天然齐全：端侧 + IoTDA + 云端 + 鸿蒙告警，不需要硬凑。
4. 方向 1 的"离线可用"在方向 2 里是**必须能力**（楼道/宿舍断网也报警），两者天然融合，不冲突。
5. 预算友好：一个智能插座采集模块 + 一块开发板 + 云资源，千元内可控。

**如果团队更想打技术硬仗**，就把方向 1 独立做深（端侧模型量化 + 断网演示 + 延迟对比），技术分最高，但要预留更多学习时间。

## 九、本条经验（写下来提醒未来的自己）

1. **先做竞品调研，再提方向。** 任何"我觉得很新"的想法，先搜一遍大厂产品。
2. **判断创新看"缝隙"不看"功能"。** 问自己：过去这件事为什么做不到？是没网、没算力、成本太高、还是没人干？
3. **指标先想好怎么测。** 测不出来的创新，决赛复现时一定翻车。
4. **华为栈要"深用"不要"蹭用"。** 用 2–4 个栈解决一个真问题，比用 10 个栈做个 Demo 强。
