# 13 · 换方向：候选评估与推荐

> 背景：原方向（单元级非侵入式用电识别）因**区分度不足 + 技术纵深弱**放弃。
> 原则：**不找"无人区"，找"前人也做得不好、我们能测出改进"的点。**
> 本文给出 4 个候选、市场核查、打分与推荐。**确认后再改写 00–12 的正文档。**

---

## 1. 上一方向为什么放弃（复盘，避免重犯）

| 问题 | 具体表现 |
| --- | --- |
| 区分度不足 | 单元级非侵入式识别 = 云南电网已工程化（15 分钟数据、88%、省级案例） |
| 技术纵深弱 | 核心可退化为"阈值 + 规则"；NILM 是成熟领域 |
| 差异偏工程 | "离线/低成本/无电网数据"是部署属性，不是技术突破 |
| 硬指标不确定 | "分钟级检出"只是承诺，没数据 |

**教训**：选方向时，先问"**前人在这个点上做到什么程度？我们能在哪个可测指标上超过它？**"

---

## 2. 选题标准（从赛题与往届提炼）

| 标准 | 来源 |
| --- | --- |
| 具体缝隙，不是泛场景 | 赛题"新场景或传统场景新突破" |
| 有一个可测的技术硬指标 | 往届一等奖都有（时延、精度、预警提前量） |
| 数据能合法拿到 | 决赛要复现，不能靠买不到的数据 |
| 5 周 / 3 人 / 无特殊硬件可完成 | 我们的实际约束 |
| 能落到华为云（CodeArts/RDS/Redis/MaaS） | 赛题硬要求 |
| 有社会价值或行业价值 | 往届获奖作品的共性 |

---

## 3. 四个候选与市场核查

### 候选 A：政策/法规的**条款级匹配与冲突检测**（面向中小企业）

**做什么**：企业填写画像（行业、规模、地区、研发投入等）→ 系统输出**可申报政策清单**，每条附**条款级引用**、申报条件、截止时间、材料清单，并提示**政策冲突/已废止**。

**市场核查**：
- 政府已有"惠企政策平台"（武汉、南阳等），但多为**关键词检索 + 人工解读**；
- 开源有 clause-level RAG（合同/建筑规范），说明"条款级引用"技术可行，但**面向中小企业资格推理 + 冲突/时效检测**的产品少；
- **数据优势**：法律法规、政策文件是**公开的**，无版权障碍（不像行业标准）。

**技术核心（可测）**：
1. 条款级检索（不是段落级）；
2. 申报条件抽取 → 转成可执行规则 → 对企业画像做**资格判定**；
3. **跨文件冲突检测**（同一事项不同部门/层级规定不一致）；
4. **时效性**（废止/修订/过渡期）；
5. 证据链（每条结论给原文出处）。

**指标**：条款召回率、引用准确率、资格判定准确率、冲突检测 F1。

**华为栈**：CodeArts 开发；RDS（pgvector 存条款向量）；MaaS（Pangu/DeepSeek 做抽取与判定）；OBS 存原文；云上部署与迭代。

**风险**：RAG 应用常见，评委可能说"不就是知识库问答" → 必须靠**冲突检测 + 资格判定 + 条款级引用**三个硬点撑住。

---

### 候选 B：古文字（甲骨文/简帛）**少样本识别与字形检索**

**做什么**：上传拓片/照片 → 识别字形 → 检索同字形/演变 → 辅助考释。

**市场核查**：
- 有公开基准 **Ancient-Bench**（2026）与甲骨文开放数据集（ROBC 等）→ 数据可得；
- 汉王等有古籍 OCR 产品；学术论文多 → **不是无人区**；
- 商业产品少，但"OCR 换皮"风险高。

**技术核心**：长尾少样本、字形结构建模、跨介质（拓片/照片/摹本）域偏移；指标：top-1/top-5、少样本增益。

**华为栈**：ModelArts 训练、Pangu 多模态、OBS。

**风险**：需要一定的模型能力（团队 AI 弱）；数据清洗量大；评委可能认为"识别任务已有基准"。

---

### 候选 C：听障人士**家居声音事件助手**（鸿蒙端侧）

**做什么**：手机/手表识别门铃、烧水、婴儿哭、烟雾报警、玻璃破碎等，震动+文字提醒。

**市场核查**：
- 已有产品/研究：eyeHear、Lisnen、SoundWatch（微软）→ **撞车明显**；
- 华为手机已有"环境音识别"相关能力 → 生态内也有。

**技术核心**：音频事件检测 + 个性化（每户声音不同）+ 端侧低延迟；指标：F1、延迟、模型大小。

**华为栈**：鸿蒙、MindSpore Lite、星闪、云迭代。

**风险**：竞品多；鸿蒙开发量在 5 周内偏大；差异化只能靠"个性化 + 中文家居 + 离线"。

---

### 候选 D：AI Agent 的**可靠性（验证 + 自愈）**

**做什么**：Agent 执行长任务（下单/对账/工单）时，自动检测错误、回滚、重试，并给出验证证据。

**市场核查**：
- LangSmith、AgentOps、Diagrid 等已在做可观测/可验证执行；Google 也在讲"受治理的自进化 Agent"；
- 学术上"self-healing agent"是热点 → **工具层竞争激烈**。

**技术核心**：任务分解 + 工具调用 + 验证器 + 故障注入评测；指标：任务成功率、恢复率、平均恢复时间。

**华为栈**：MaaS、RDS/Redis、CodeArts。

**风险**：更像"工具/框架"而非"应用"；赛题2 才是 Agent 专项；演示需构造沙箱。

## 4. 打分矩阵

权重：创新缝隙 30%、技术纵深 25%、可行性 20%、数据可得 10%、华为契合 10%、演示力 5%

| 候选 | 创新缝隙 | 技术纵深 | 可行性 | 数据 | 华为 | 演示 | 加权 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **A 政策条款匹配** | 70 | 65 | 90 | 95 | 90 | 80 | **75.5** |
| B 古文字 | 65 | 85 | 55 | 80 | 85 | 85 | **72.0** |
| C 听障声音 | 55 | 70 | 70 | 85 | 90 | 75 | **68.8** |
| D Agent 自愈 | 65 | 80 | 60 | 90 | 85 | 60 | **72.0** |

> 打分是判断，不是事实；差异在 3–7 分内，说明**没有显著最优**，选"最容易做出硬指标"的。

## 5. 推荐：候选 A（政策条款级匹配与冲突检测）

### 5.1 为什么是它
1. **数据零障碍**：法律法规/政策公开，决赛可复现；
2. **指标硬且易测**：条款召回、引用准确、资格判定、冲突 F1，都能在 5 周内做出来；
3. **技术纵深可造**：冲突检测 + 资格规则化 + 时效性，比"知识库问答"高一层；
4. **社会价值明确**：中小企业"找不到、看不懂、不敢报"政策，是真实痛点，且与政策导向一致；
5. **华为栈天然契合**：CodeArts 开发 → RDS(pgvector) → MaaS → 云部署 → 迭代，全链路可展示；
6. **团队能力匹配**：以工程为主（检索、结构化、前端），弱 AI 也能做，MaaS 补模型能力。

### 5.2 一句话定位
> **把"政策文件"变成"可执行的企业资格判定 + 条款级证据链"**，而不是又一个政策问答机器人。

### 5.3 三个必须做出的硬点（否则退化成普通 RAG）
| 硬点 | 指标 |
| --- | --- |
| 条款级引用（不是段落级） | 引用准确率 ≥ X% |
| 资格判定（条件 → 规则 → 企业画像） | 判定准确率 ≥ X% |
| 冲突/时效检测 | 冲突 F1 ≥ X% |

### 5.4 5 周计划（初赛）
| 周 | 任务 | 产出 |
| --- | --- | --- |
| W1 | 选 1 个地区 + 1 个行业（如"某市制造业中小企业"），收集 30–50 份政策；定义企业画像字段 | 政策库 + 字段表 |
| W2 | 条款切分 + 条件抽取（MaaS）+ 检索（RDS pgvector） | 可检索的条款库 |
| W3 | 资格判定 + 冲突/时效检测；建立 20–30 条评测集；跑基线（关键词检索 vs 我们） | 指标表 |
| W4 | 前端 Demo + 材料（模板1）+ 演示视频 | 初稿 |
| W5 | 改稿、提交 | 已提交 |

### 5.5 风险与对策
| 风险 | 对策 |
| --- | --- |
| 被说"就是 RAG" | 开场就讲"条款级 + 资格判定 + 冲突检测"三件套；现场演示同一政策不同部门的冲突 |
| 政策数据太多做不完 | 只做一个地区、一个行业、30–50 份 |
| 资格条件抽取不准 | 先做"可形式化"的条件（金额、年限、规模），模糊条件标"需人工确认" |
| 评委质疑商业价值 | 对标政府"惠企平台"的不足（只能搜、不能判） |

---

## 6. 备选：如果你们更想做"技术硬"的

选 **B 古文字**：技术纵深更高（少样本/域偏移），但 5 周内做出可信指标难度大，且需要模型训练能力。
如果队里有人愿意啃模型，B 的上限比 A 高；否则 A 更稳。

---

## 7. 需要你们确认的三件事

1. **接受纯软件方向吗？**（不碰硬件，仓库代码大部分要重写）
2. **政策数据有渠道吗？** 你们所在省市有没有熟悉的行业/园区（能拿到一手需求）？
3. **愿意做 RAG + 规则引擎吗？** 这是 A 的核心工作量。
