# 14 · 校正：项目定位与架构（以比赛为目标，回到"断网可用 + 有网迭代"）

> 本文是一次**方向校正**，起因是：
> ① 把项目当成了"要做成产品"，导致范围不断膨胀；
> ② 忘了 05 文档里最初的架构设想——**"断网也能判断；有网时同步、迭代模型"**。
> 并明确作废 13 文档中的一条错误判断。

---

## 1. 先确认项目定位（这是总纲）

> **本项目是竞赛项目，核心目标是获奖，不是做成可上市产品。**

| 因此 | 我们 |
| --- | --- |
| 不需要考虑 | 量产、认证、运营体系、售后、用户手册、多租户权限、渠道、定价 |
| 不需要考虑 | 真实部署的完整性（如每个插座怎么装、谁来维护） |
| **需要做到** | **核心技术可实现 + 效果可量化 + 可复现 + 讲得清创新性** |

**判据：任何工作，问一句"这能不能帮我们拿分？" 答不上来就不做。**

---

## 2. 原始架构（05 文档原文，必须恢复）

> "**端侧推理，断网也能判断和本地报警**；**有网时同步、迭代模型**。"
> "识别模型跑在采集端（开发板/MCU/鸿蒙设备），不依赖云；**云端只做批量复盘与模型迭代**。"

```
        端侧（离线可用）                华为云（有网时）
   ─────────────────────         ─────────────────────────
    推理判断、本地告警      ──上传─→  误报样本 / 未知设备
                                        ↓ 批量复盘
    不能更新时照常工作      ←─下发─   重训 + 模型版本发布
    （继续用现行模型）                 （RDS / Redis / MaaS）
```

**两端缺一不可。**

---

## 3. 为什么必须保留"云端迭代"（三个理由）

### 3.1 这是赛题1 的落点
赛题1 的名称是"**基于华为云产品**打造 AI 创新应用"，要求体现"需求理解、代码生成、项目构建、问题修复、部署上线"的价值。
**如果方案里没有云，华为云就成了纯搬运，赛题的核心考察点直接落空。**

### 3.2 没有迭代，方案就退化成"一颗单片机"
纯端侧推理只是一个嵌入式功能。加上"云端复盘 + 模型下发"，才有：
- **边端云协同**的架构叙事
- **数据反哺**的闭环逻辑
- 与电网方案"主站推理"形成**结构性差异**

### 3.3 它是"离线可用"能成立的前提
端侧模型必须足够小、足够快，才能离线跑；而小模型必然在长尾场景下不够准。
**靠云端积累样本、迭代模型，才能让端侧小模型持续变好。**
→ 端侧小 ≠ 弱，因为有云端在后面补。

---

## 4. 作废与更正（重要）

### 4.1 作废
13 文档中曾写道：

> "**离线部署 = 模型一旦出厂就无法频繁迭代。** 云端方案可以靠持续回传数据不断重训，而我们的设备没有网、不传数据……"

**该判断错误，作废。** 它把"断网可用"误读为"永不离线"，从而否掉了云端迭代——与 05 文档的原始设想直接冲突。

### 4.2 更正
| 错误表述 | 正确表述 |
| --- | --- |
| 离线 = 不能迭代 | **离线 = 断网时也能工作；有网时上传样本、云端迭代、下发新模型** |
| 端侧是唯一执行体 | **端侧负责判断，云端负责进化** |
| 泛化是"离线的债" | **泛化是"迭代闭环的输入"**：端侧上报不认识/判错的样本，云端据此改进 |

---

## 5. 两条技术路径的重新定位

| 路径 | 原来的说法（勿用） | 校正后的定位 |
| --- | --- | --- |
| **B 少样本 / 未知设备泛化** | "离线就必须泛化，是在还债" | **让迭代闭环转得动**：能识别"我不认识"，才知道该上报什么样本 |
| **A 声电双模** | "增强版分支，可选" | **提升端侧判断质量**，减少无谓上传；作为深度的加分项 |

**核心叙事**：
> 端侧小模型负责"当场判断"，云端负责"持续变聪明"。
> 端侧知道自己"不认识什么"，云端才知道"该学什么"。

## 6. 初赛阶段具体做到哪一步

| 环节 | 初赛要求 | 是否真做 |
| --- | --- | --- |
| 端侧推理 / 断网可用 | 有指标、能演示 | ✅ 用**笔记本断网**演示，不买板子 |
| 数据采集与统计 | 有真实数据 | ✅ 真采 |
| 模型训练与评估 | 有混淆矩阵、准确率 | ✅ 真做 |
| **云端复盘与模型迭代** | **讲清架构即可** | ⚠️ **不实现，只画图 + 写清机制** |
| RDS / Redis / 代码生成 | 总决赛才要求 | ❌ 初赛不做 |
| 分级处置、禁用机制 | 答辩储备 | ❌ 不实现 |

**一句话：初赛把"断网可用"做实，把"有网迭代"讲清。**

> 这不是偷懒——赛题初赛只要求材料，云端迭代属于架构设计层面的内容，
> 在方案书里用一张图 + 一段机制说明即可，**不需要真的部署**。

## 7. 竞赛视角下的取舍原则（以后遇到新想法就套这个）

| 问题 | 处理 |
| --- | --- |
| 能不能帮我们拿分？ | 不能 → 不做 |
| 是不是初赛材料需要的？ | 不是 → 记下来，等决赛 |
