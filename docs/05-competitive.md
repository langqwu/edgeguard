# 05 · 方向二「电气火灾预警」竞品拆解与我们的核心优势

> 用途：回答"方向二市面上也有人做，我们的核心优势在哪"。
> 结论先行：**在"识别充电行为"这个主战场上，我们没有优势——资源型对手（电网、电气厂商）已经占位。我们唯一能打的是它明确承认的三块短板，以及一块它没做的"事前风险状态"。**

---

## 一、先把竞争对手摆齐（四类，按威胁从高到低）

### 1.1 威胁最高的：云南电网「非侵入式电动自行车入户充电智能识别」

来源：[云南省"人工智能+"典型案例之四（2026-08-18）](http://yndrc.yn.gov.cn/html/2026/benweidongtai_0818/28070.html)

| 维度 | 它的做法 |
| --- | --- |
| 数据源 | **电网已有的 15 分钟粒度用电信息采集系统**（智能电表），零硬件改造 |
| 算法 | CNN（局部波形）+ BiLSTM（长时序）融合；无监督聚类构建充电特征库 |
| 指标 | 50 余个台区试运行，识别 242 户，现场核实 133 户，**准确率 88%** |
| 覆盖 | 常规 2–8 小时慢充；能识别"电池拆卸后入户充电"这一监管盲区 |
| 部署成本 | **零硬件改造，单户节省百元以上**，改主站采集方案即可 |
| 治理闭环 | 短信提示 → 网格员上门 → 消防部门数据联动 |
| 身份 | 省发改委认定的"人工智能+"典型案例，电网公司主导 |

**它自己的原文，把我们的路堵得很清楚**：

> "现有方案依赖硬件加装，成本高、覆盖有限……高频非侵入负荷识别方案，需在电表端加装高频采集模块，实现 kHz 级电压电流采样，单户改造成本超百元……视频 AI 识别方案，依赖电梯、楼道摄像头，存在视角遮挡、隐私合规风险，且无法识别电池拆卸后带入家中充电的场景"

**翻译一下**：凡是"靠装硬件做识别"的路线，它都已经用"零硬件 + 电网数据"降维打击了。**如果我们做的还是"装个传感器识别充电"，我们在成本上永远输。**

### 1.2 威胁中等的：电气安全硬件厂商（如安科瑞）

来源：[安科瑞智慧用电方案（2026-09）](http://www.acrelwmm.com/jsshow-491269.html)

| 维度 | 它的做法 |
| --- | --- |
| 产品 | 智慧用电探测器（漏电/温度/故障电弧/过载）、智能微断、限流式保护器 |
| 架构 | 云-边-端三层；网关本地断网缓存，网络恢复补传 |
| 能力 | **测电气量、判故障类型**（故障电弧、漏电、过温） |
| 短板 | **不识别"这是什么电器在用电"**；按点位收费，产品线重 |
| 身份 | 上市公司（300286），渠道与资质齐全 |

**它的软肋**：它是"电气参数监测"，不是"用电行为识别"。它能告诉你"这个回路有故障电弧"，但说不出"这是电瓶车在充电"。

### 1.3 威胁中等的：校园/宿舍专用方案

来源：[AI 智能断路器+插座识别宿舍违规电器](http://www.hzsfbr.com/Article-648246.html)、[安科瑞宿舍用电方案](http://www.acreldb.com/Article-633166.html)

- 用智能断路器或智能插座，配合功率阈值/波形特征识别"违规大功率电器"。
- **已经在高校批量部署**，说明这个场景不新。

### 1.4 学术与开源侧

- NILM（非侵入式负荷监测）是成熟研究领域，EV 充电检测有专门论文（如 [EVSense](https://api.repository.cam.ac.uk/server/api/core/bitstreams/4ada08b5-530f-4dcf-a2f7-185abdd435f2/content)、[馈线级 EV 充电检测](http://arxiv.org/pdf/2312.01887v1)）。
- **含义**：算法不是护城河，谁都能复现论文。

## 二、残酷的结论：我们没有"资源型优势"

对比一下双方手里的牌：

| 资源 | 云南电网 | 安科瑞 | 我们（3 名本科生） |
| --- | --- | --- | --- |
| 智能电表 15 分钟数据 | ✅ 全网覆盖 | ❌ | ❌ |
| 台区/用户规模 | ✅ 50+ 台区 | ✅ 大量项目 | ❌ |
| 硬件产品线与资质 | 中 | ✅ 齐全 | ❌ |
| 电网/消防渠道 | ✅ | ✅ | ❌ |
| 政府背书 | ✅ 省级典型案例 | 商业客户 | ❌ |
| **算力与云资源** | 中 | 中 | ✅ **华为云代金券 + MaaS** |
| **端侧/鸿蒙/星闪能力** | 弱 | 弱 | ✅ **团队强项** |
| **开源与可复现** | ❌ 闭源 | ❌ 闭源 | ✅ **赛题要求开源** |
| **试错成本** | 高（涉电网） | 高（涉产品） | ✅ **极低** |

**所以核心优势不能从"资源"里找，只能从"他们没有做、或做不了的事"里找。**

## 三、它明确承认的三块短板 = 我们唯一能站的位置

### 短板 1：它依赖电网数据，**没有电网数据的场景它进不去**

- 电网方案的前提是"智能电表 + 15 分钟采集"。**宿舍、出租屋、群租房、小商铺、仓库、老旧小区自管配电**——这些场景的数据不在电网手里，物业/房东/学校拿不到。
- 但**恰恰是这些场景风险最高**：出租屋群租、宿舍违规充电、小商铺夜间充电。
- **我们的位置**：给"拿不到电网数据"的场景，提供一个**不依赖电网、不依赖摄像头**的识别能力。

### 短板 2：它依赖**云端**推理与主站系统，**没网就失效**

- 电网方案的推理在主站/云侧；安科瑞虽然有网关断网缓存，但**判断仍在平台**。
- 而风险场景（地下室、楼道、老旧小区、工地）恰恰**弱网/断网**。
- **我们的位置**：**端侧推理，断网也能判断和本地报警**；有网时同步、迭代模型。这一条可用"拔网线演示"一击证明。

### 短板 3：它做的是"**识别行为**"，做不到"**评估风险**"

- 云南电网识别的是"有没有在充电"；安科瑞测的是"电气参数是否超限"。
- **两者都不回答**：这台车/这块电池/这个充电器，**离热失控还有多远**。
- 电动自行车火灾的主因是**电池老化、改装电池、劣质充电器**，而不是"充电"本身。
- **我们的位置**：从"行为识别"升级为"**风险状态评估**"——输出风险分而不是报警。

### 附加短板：它是闭源的

- 电网与厂商方案都闭源，**无法被第三方复现、改进、适配新场景**。
- 赛题要求开源，**开源本身就是一种竞争力**：谁能成为"低采样率充电识别"的开源基座 + 公开数据集 + 评测协议，谁就占住了生态位。

## 四、我们的核心优势（三条，按可信度排序）

### 优势 A（最硬）：**端侧在环 —— 断网可用、毫秒级本地判断**

| 项目 | 说明 |
| --- | --- |
| 是什么 | 识别模型跑在采集端（开发板/MCU/鸿蒙设备），不依赖云；云端只做批量复盘与模型迭代 |
| 为什么对手难跟 | 电网方案架构上就是"主站推理"；安科瑞的判断逻辑在平台。要改成端侧，等于重构产品 |
| 怎么证明 | **现场拔掉网线，端侧仍然报警**；给出本地推理时延（ms 级）vs 云端（百 ms–秒级） |
| 量化指标 | 断网可用率 100%、本地判断时延、离线准确率 vs 在线准确率 |
| 风险 | 模型要能塞进端侧（需量化压缩），这是真功夫，但 CodeArts + MindSpore Lite 可辅助 |

### 优势 B：**无电网数据场景的"平民化"识别**

| 项目 | 说明 |
| --- | --- |
| 是什么 | 用低成本采集（插座级电流/电压，甚至用光照/温湿度辅助）在**没有智能电表**的场景做识别 |
| 为什么对手难跟 | 电网方案天然绑定电网；厂商方案按点位收费，宿舍/出租屋这种"高数量低单价"市场他们不划算 |
| 怎么证明 | 部署时间（分钟级）、单点成本（几十元）、无需断电施工 |
| 量化指标 | 单点成本、部署耗时、识别准确率 |
| 风险 | 单点成本压不下去就失去意义；需要和"电网方案"明确划清场景边界 |

### 优势 C（最有想象力，但最难）：**从"识别行为"到"评估风险状态"**

| 项目 | 说明 |
| --- | --- |
| 是什么 | 不回答"在不在充电"，而回答"这次充电有多危险"——基于充电曲线形态、充电器特征、电池老化特征输出风险分 |
| 为什么对手难跟 | 需要电池/充电器的真实失效样本与领域知识，电网与厂商都不做这件事（他们做"合规判定"，不做"寿命与风险"） |
| 怎么证明 | 同一场景下，正常电池 vs 老化/改装电池的曲线特征差异；风险分与人工判定的相关性 |
| 量化指标 | 风险分与人工标注的一致性、危险样本召回率 |
| 风险 | **需要真实的老化/改装电池样本**，获取和实验都有难度；做不深就会变成"又一个阈值报警" |

### 一个可选的"技术纵深"方向：声学前兆

锂电热失控前会有**电芯排气（vent）**产生的气流声与电解液分解的高频声，属于可探测的物理前兆。学术上有声学探测研究，但**消费级低成本产品极少**。

- 价值：与电流波形形成**双模态**——电流告诉你"在充电"，声音告诉你"快不行了"。
- 挑战：需要 48kHz 以上采样、麦克风阵列、可控实验；**没有真实热失控样本很难验证**（且实验有安全风险）。
- 建议：**作为"未来工作"写进方案，不作为主演示**，除非能找到安全的替代样本（如可控的劣质充电器异响）。

## 五、诚实的判断：这些优势够不够？

| 问题 | 回答 |
| --- | --- |
| 我们有"资源型"优势吗？ | **没有**。电网、厂商、政府渠道都不在我们手上。 |
| 我们有"技术型"优势吗？ | **有，但只在"端侧在环 + 断网可用 + 无电网数据场景"这一窄缝上。** |
| 这条缝够不够大？ | 够做**一个能获奖的作品**（缺口径清晰、可演示、有指标），但**不够撑起一个商业公司**。赛题要的是前者。 |
| 最大的风险是什么？ | 评委说"这不就是电网/厂商方案的简化版"。**破解方式：开场就讲"他们做的是有电网数据的场景，我们做的是他们进不去的场景 + 断网也能用"，并现场拔网线。** |

## 六、两条路，选一条

### 路线甲：修方向二 —— 收缩到"无电网数据 + 弱网"的缝隙

**定位一句话**：
> 给拿不到电网数据、又装不起摄像头的场景（宿舍、出租屋、群租房、小商铺），提供一个**断网也能判断、不需要摄像头**的用电风险识别盒子。

**四层创新对应**：
- 场景：无电网数据的高风险小场所（电网方案进不去）
- 交付物：一个端侧会判断的盒子 + 闭环处置（不是"又一个报警器"）
- 技术：端侧推理 + 星闪本地组网 + 鸿蒙告警 + 云端模型迭代（边端云三级）
- 指标：断网可用、本地时延、单点成本、识别准确率

**3 分钟 Demo**：
1. 接上一个"违规充电器"→ 端侧 1 秒内本地声光/鸿蒙告警（**此时网线是拔掉的**）。
2. 插上正常电器（电热水壶/空调）→ 不误报。
3. 插回网线 → 云端同步，App 看到历史与风险分；模型在云端迭代后推送到端侧。
4. 拔掉路由器，用星闪点对点把告警传到另一台鸿蒙设备（**无网络本地组网**）。
5. 对比：电网方案需要智能电表数据；我们只需要一个盒子。

**风险**：仍然要面对"识别准确率不如电网 88%"的质疑。**必须把话术设计好**：我们不比"有电网数据的准确率"，我们比"没有电网数据时能不能做"。

### 路线乙：换方向 —— 回到"离线端侧 AI"这条更宽的缝

**定位一句话**：
> 把 AI 搬进没有网络的地方（林区、渔船、矿井、地下室、偏远卫生院）。

**为什么更稳**：
- 大厂全部押"云端 API"，**离线端侧是结构性空白**，不是产品功能差异。
- 指标体系干净：模型压缩比、首字延迟、离线准确率、单设备成本。
- 演示极强：拔网线，AI 照常工作。
- 与团队强项（硬件/嵌入式/鸿蒙）高度匹配。

**代价**：端侧部署学习曲线陡，需要开发板，且要选一个具体行业场景（否则会变成"通用离线助手"）。

### 我的建议

> **走路线甲，但把它当成"路线乙的第一个落地场景"来写。**
> 叙事上先讲"离线端侧 AI"这个大命题（结构性空白），再落到"电气安全"这个具体场景（有真实痛点、有竞品可对比、有硬指标）。这样既躲开"电瓶车识别"的红海，又保住方向的落地性。

## 七、下一步要验证的 3 件事（不通过就换路线）

| # | 验证什么 | 通过标准 | 不通过 |
| --- | --- | --- | --- |
| 1 | 端侧跑模型：开发板上跑通一个量化后的分类模型 | 单次推理 < 200ms，可离线 | 换路线乙的其他场景，或退回云端+弱网缓存 |
| 2 | 数据可得性：采到"电瓶车充电器 / 大功率电器 / 正常家电"三类真实波形 | 每类 ≥ 20 段 | 用公开数据集（PLAID 等）先跑通算法 |
| 3 | 断网演示可行性：拔网线后端侧仍能判断并本地告警 | 现场可复现 | 说明端侧方案不成立，必须重设计 |

## 八、一句话回答你的问题

> **我们的核心优势不是"识别得更准"，而是"在他们进不去的场景里、在网络不通的情况下，仍然能判断"。**
> 这个优势目前只是**技术选择的优势**，还不是**资源壁垒的优势**——所以必须靠"断网演示 + 成本对比 + 真实场景数据"把它变成评委看得见的差异，否则它会被当成"简化版电网方案"。
