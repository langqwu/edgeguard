# 产品设计决策记录（DDR）

> 目的：把三个关键设计选择写清楚，避免方案书里自相矛盾，也方便答辩时口径一致。
> 对应问题：①要不要识别所有电器？②只做预警还是也做控制？③每个插座都装板子现实吗？

---

## 决策 1：判断什么？——从"识别电器"改为"判断插座越界"

### 1.1 问题
同样功率的用电，在不同插座上意义不同：2000W 在宿舍插座是违规，在食堂后厨是正常。
如果模型只回答"这是什么电器"，则：电器种类无穷、永远识别不全、换设备就要重训。

### 1.2 决策
**不做"万能电器识别"，改做两层结构：**

**第一层｜负载形态识别（4 类，不追求具体型号）**

| 形态 | 典型设备 | 功率曲线特征 |
| --- | --- | --- |
| 恒功率长平台 | 电瓶车充电器、电源适配器 | 阶跃上升 → 长时平台 → 缓降 |
| 短时高压阻性 | 电热水壶、热得快 | 快速到峰值 → 到时突降归零 |
| 剧烈跳变 | 吹风机、电机类 | 功率随档位反复跳变、方差大 |
| 平稳低功率 | 待机、小电器 | 功率低且稳定 |

**第二层｜每个插座的"允许规则"（配置项，不需要训练）**

```
允许最大功率      : 例如 800 W
允许最大连续时长  : 例如 120 分钟
允许时段          : 例如 08:00–20:00
允许的负载形态    : 例如 禁止"恒功率长平台"
```

判定逻辑：`形态识别结果 + 该插座的规则 → 越界 / 正常`。

### 1.3 附加决策：环境自学习（异常检测优先）

- 设备装上后先跑 **7 天"只学不报"**，学习该插座的夜间基线、峰值分布、每日用电时段。
- 之后偏离基线（如夜间出现持续 1 小时以上的中功率平台）才上报。
- **好处**：能处理没见过的新电器，不依赖穷举训练。
- 预设模式（宿舍 / 出租屋 / 商铺 / 车间）作为**初始模板**，仍需本地自适应。

### 1.4 对指标的影响
- 除"识别准确率"外，须增报：**误报率**（异常检测最怕误报）、**基线学习所需天数**、**新设备泛化表现**。

## 决策 2：只预警，还是也做控制？——做分级闭环控制

### 2.1 决策
**做闭环**，从"识别"延伸到"分级处置"。这是与仅做告警的同类作品的关键差异。

| 级别 | 动作 | 触发条件 | 安全约束 |
| --- | --- | --- | --- |
| L1 | 本地声光告警 + 推送 | 首次发现、低风险 | 无 |
| L2 | **延时断电**（倒计时 60 s，可撤销） | 确认违规充电 | 必须可撤销、留操作日志 |
| L3 | **限功率**（限流，不直接断） | 需保障基本用电的场景 | 由智能断路器执行 |
| L4 | 回路隔离 + 整改记录 | 连续违规 | 需人工复核后复位 |

### 2.2 硬件增量
- 一个继电器模块或直接接智能断路器，**增量成本约 ¥10–20**。
- 原型阶段可选：5V 继电器模块 + 延时断电逻辑即可演示。

### 2.3 边界与合规（方案书必须写明）
1. 是**保护性断电**，不是惩罚性断电；必须可撤销、有倒计时、有日志。
2. 只切**插座回路**，不切总闸。
3. 提供**物理复位**，避免断电后无法恢复。
4. **不替代**原有断路器的短路/过载保护，定位为补充防护。
5. 断电前给出可感知的倒计时提示（声/灯/推送）。

### 2.4 答辩价值
- 应用价值（40%）要求"技术架构完备、可落地"——闭环处置是最直观的证明。
- 与竞品对比时，"识别 + 分级处置"比"识别 + 告警"高一个产品层级。

## 决策 3：产品形态——不是每插座一台电脑，而是把算法嵌进去

### 3.1 问题
如果每个插座旁都要放一块开发板，产品在成本上不成立。

### 3.2 决策
**产品形态是嵌入智能插座/智能断路器的算法模块，不是外部盒子。**

| 形态 | 组成 | 成本 | 用途 |
| --- | --- | --- | --- |
| **研究原型**（当前） | 开发板 + PZEM-004T + 继电器 + 插座盒 | 约 ¥300/套 | 只验证可行性、产出数据 |
| **工程样机** | 计量芯片 + MCU + 继电器，嵌入插座 | **BOM 约 ¥15–30/点** | 证明"装得起" |
| **产品** | 算法模块 / SDK 授权给插座厂商 | 边际成本近 0 | 商业模式 |

### 3.3 单位经济性对比（方案书核心论据）

| 方案 | 单点/单户成本 | 覆盖场景 |
| --- | --- | --- |
| 电网高频采样改造 | **上百元/户**，全域投入数亿 | 有智能电表的居民台区 |
| 电气安全厂商硬件 | **数百元/点位** | 九小场所、厂房、园区 |
| **我们（嵌入方案）** | **¥15–30/点** | 宿舍、出租屋、群租房、小商铺 |

### 3.4 答辩口径（重要）
不要回答"这是客户要考虑的事"。正确答法是主动给出形态演进：

> "开发板只是研究阶段的验证载体。我们验证的核心是一套算法：只要计量芯片加一颗 MCU 就能跑，单点成本 15–30 元。量产形态是把它嵌进已有的智能插座与智能断路器，而不是给每个插座加一台电脑。"

### 3.5 与"端侧推理"的关系
- 端侧推理的能力边界不变（断网可用、毫秒级、数据不出户）。
- 但**载体从"开发板"变成"插座里的 MCU"**：需要模型足够小（量化后几十 KB 到几百 KB 量级）。
- 这一点要在方案书里作为技术挑战写出来：**模型轻量化是产品化的前提**。

## 三个一定要记住的答辩句

1. **"我们不识别所有电器，我们判断这个插座的用电有没有越界。"**
2. **"识别只是第一步，我们做到分级处置，而且断电可撤销、有记录。"**
3. **"不是每个插座加台电脑，是把算法嵌进插座，单点 15–30 元。"**
