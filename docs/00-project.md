## 1. 项目是什么

**EdgeGuard —— 断网可用的用电风险识别**：在插座/配电回路侧采集电压、电流、功率，用轻量模型在**端侧**判断是否存在违规充电、大功率电器等用电越界行为，**断网也能判断与告警**；有网时上传样本，由**华为云**复盘并迭代模型后下发。

参加：第十一届华为 ICT 大赛（2026-2027）中国创新赛 · **赛题1：基于华为云产品打造 AI 创新应用**

## 2. 定位：这是竞赛项目，不是产品项目

> **核心目标是获奖，不是做成可上市产品。**

| 不需要做 | 需要做到 |
| --- | --- |
| 量产、认证、运营体系、售后、说明书 | 核心技术可实现 |
| 多租户权限、计费、渠道、定价 | 效果可量化、可复现 |
| 真实部署的完整性（谁来装、谁来维护） | 创新性讲得清 |

4. 会不会拖长关键路径？
5. 是否偏离"断网可用 + 云端迭代"？

## 3. 架构：端侧判断 + 云端进化（两级，缺一不可）

```
      端侧（离线可用）                      华为云（有网时）
 ──────────────────────          ───────────────────────────
   推理判断、本地告警        ──上传─→   误报样本 / 未知设备样本
                                          ↓ 批量复盘
   断网时照常工作            ←─下发─    重训 + 模型版本发布
   （继续用现行模型）                    （RDS / Redis / MaaS）
```

### 3.1 为什么两端都必须有

| 环节 | 放在哪 | 理由 |
| --- | --- | --- |
| **判断** | 端侧 | 断网/弱网、毫秒级响应、数据不出户、成本低 |
| **复盘与迭代** | **华为云** | ① 赛题1 的名称就是"基于华为云产品"，云是必答题；② 端侧小模型必然在长尾场景不够准，靠云端积累样本持续变好；③ 与电网方案"主站推理、断网失效"形成结构性差异 |

**⚠️ 曾经犯过的错误（勿重犯）**：曾把"断网可用"误读为"永不离线"，进而认为"离线就不能迭代"。**错误。** 正确理解是：断网时用现行模型继续工作，有网时上传样本、云端重训、下发新版本。

### 3.2 一句话叙事

> **端侧负责"当场判断"，云端负责"持续变聪明"。**

## 4. 核心设计决策

### 4.0 测量位置：单元级单点（不是插座级）

**一个设备装在单元的入户回路上，覆盖一整个单元**（一间宿舍 / 一户出租屋），而不是每个插座装一个。

```
单元总进线 → [一个计量点：PZEM + 端侧推理] → 插座1/插座2/…/空调
```

看到的是所有电器**叠加后的总功率**，从中检出"有没有充电 / 有没有大功率越界"（非侵入式）。
与电网方案同一粒度，但**不依赖电网数据、判断在端侧、断网可用**；成本是"一个单元一个点"，不是"一个插座一个点"。

> 完整论证、混合负载实验与答辩口径见 [`10-unit-level-monitoring.md`](10-unit-level-monitoring.md)。

### 4.1 判断什么：不识别电器，判断"越界"

**问题**：同样功率在不同插座意义不同（2000W 在宿舍违规，在食堂后厨正常），且电器种类无穷，永远识别不全。

**决策**：两层结构。

**第一层｜负载形态识别（4 类，不追求具体型号）**

| 形态 | 典型设备 | 曲线特征 |
| --- | --- | --- |
| 恒功率长平台 | 电瓶车充电器、电源适配器 | 阶跃上升 → 长平台 → 缓降 |
| 短时高压阻性 | 电热水壶、热得快 | 快速到峰 → 到时突降归零 |
| 剧烈跳变 | 吹风机、电机类 | 功率随档位反复跳变、方差大 |
| 平稳低功率 | 待机、小电器 | 功率低且稳定 |

**第二层｜每个插座的"允许规则"（配置项，无需训练）**

```
允许最大功率 / 允许最大连续时长 / 允许时段 / 允许的负载形态
```

判定：`形态识别结果 + 该插座规则 → 越界 or 正常`

### 4.2 技术纵深：两个真难点（不是堆模块）

| 路径 | 做什么 | 为什么算"有技术含量" | 优先级 |
| --- | --- | --- | --- |
| **B 少样本 + 未知设备泛化** | 每类只用 3–5 样本训练；测试含**训练时没见过的电器**；报"拒识率" | 开集识别是 NILM 领域公认难题；**且是迭代闭环的输入**（端侧知道自己"不认识什么"，云端才知道该学什么） | **必做** |
| **A 声电双模融合** | 电气 + 声学（MFCC/频谱）双模态，报**融合增益** | 真多模态融合，与往届一等奖 AscendSentinel 同路数；有工程难点（时间对齐、噪声抑制、模态互补） | 看人（有人愿碰音频就做） |

**声电方案的约束**（若做，必须同时满足）：只提特征不存原始音频；仅功率突变时唤醒 3–5 秒窗口；硬件级静音开关；产品分"基础版/增强版"两档。

**不做**：电池健康判别（样本风险高）、极限压缩（初赛无板子无法实测）。

### 4.3 产品形态（答辩储备，非实施任务）

不是给每个插座配一台电脑，而是**把算法嵌进智能插座/智能断路器**：

| 形态 | 组成 | 成本 | 用途 |
| --- | --- | --- | --- |
| 研究原型 | 开发板 + PZEM + 继电器 | ~¥300/套 | 仅验证可行性 |
| 工程样机 | 计量芯片 + MCU + 继电器 | **BOM ¥15–30/点** | 证明"装得起" |
| 产品 | 算法/SDK 授权 | 近 0 | 商业模式 |

**单位经济性**（对方方案对比）：电网高频采样改造上百元/户；电气安全厂商数百元/点位；**我们 ¥15–30/点**。

### 4.4 分级处置与禁用机制（答辩储备，非实施任务）

- **分级处置**：告警 → 延时断电（可撤销、留痕）→ 限功率 → 回路隔离；边界是"保护性断电而非惩罚性"，只切插座回路，不替代原有断路器保护。
- **禁用与撤回**：拆成三层——数据采集（可撤回，法律要求）、安全保护（不可随意禁）、场所策略（管理者权限）；设备端用物理按键 + 三色灯 + 六态状态机；配误报申诉通道（**误报即高质量负样本**）。

## 4.5 区分度：靠三件事撑起来

与市面产品（云南电网、安科瑞、智能插座）相比，单纯"单元级 + 非侵入式"区分度**不够**。
真正能放大的差异是三条的组合：

1. **更快的检出**：1 秒采样 vs 电网 15 分钟，目标"充电开始后分钟级报警"（唯一技术硬指标）；
2. **只做无电网数据的场景**：宿舍、出租屋、工地临电——电网和厂商进不去的地方；
3. **能说"不认识"**：开集拒识 + 误报反馈闭环。

> 评估与 Plan B 见 [`12-differentiation.md`](12-differentiation.md)。

## 5. 差异化一句话（答辩开场用）

> "电网方案要有电网数据、判断在主站；电气厂商只能测电气参数、说不出是什么在用电；摄像头有盲区还侵犯隐私。
> **我们给拿不到电网数据、又装不起摄像头的场景，一个断网也能判断、只采电参量的盒子。**"

## 6. 三条警戒线

1. **不要为了显得有技术含量而堆方法**。一个讲透的难点，胜过五个堆上去的模块。
2. **不要按真实部署的完整性要求自己**。这是比赛，初赛只交材料。
3. **不要偏离"端侧判断 + 云端进化"**。偏离了，赛题1 的核心考察点就落空了。
