# 11 · 范围界定：核心技术 vs 完整产品

> 用途：**防止范围失控**。每当我或队友想"再加个功能"时，先看这份文档。
> 结论：**初赛只做核心技术（数据 → 模型 → 指标 → 代码），产品化一律不做。**

---

## 1. 往届获奖作品的实际深度（核实过的 5 个案例）

| 作品 | 赛事与奖项 | 做到什么程度 | 没做什么 |
| --- | --- | --- | --- |
| 《昇腾 NPU 算力平台下的 ModelEngine ViT 推理性能提升》 | 第十届 中国总决赛一等奖 | 跑通 PyTorch→ONNX→OM 优化链路，**有前后对比数据，开源全流程文件** | 无产品化、无用户、无界面 |
| 《Ascend Sentinel 校园暴力智能干预》 | 第十届 全球二等奖 | 边端云原型 + 音频与毫米波雷达试验台 | 无量产、未进校园实际部署 |
| 《MindAligner 脑机接口辅助诊断》 | 第十届 中国总决赛二等奖 | 平台原型 + 自研算法 + **论文、软著** | 无医疗器械认证、无医院落地 |
| 《U-care "Yuka" 养老机器人》 | 第十届 中国总决赛二等奖 | 实验室样机 + Demo 演示 | 无量产、无养老服务运营 |
| 《ModelEngine 病理知识问答智能体》 | 第十届 中国总决赛一等奖 | 模型微调 + 评测结果 | 无商业系统 |

### 提炼出的"参赛深度参考线"

```
必做（决定能否获奖）     ：核心技术可实现 + 效果可量化 + 可复现
加分（明显提升名次）     ：开源、论文/软著、真实场景数据
可选（少数强队会做）     ：原型系统、Demo 页面
不做（本届不需要）       ：量产设计、认证、运营体系、售后、用户手册
```

**一句话：评委看的是"你把某个技术问题解决了没有、解决到什么程度"，不是"你有没有把它做成生意"。**

## 2. 初赛的官方要求（再确认一次边界）

初赛只提交：
- 【模板1】作品信息收集表 Word（必交）
- 作品介绍 PPT / 设计文件 / 演示视频（**"如有"，可选**）

材料需体现：背景与价值、创新性、**数据集选取与处理**、**关键代码片段解读**、**可量化效果指标**。

**初赛明确不要求**：
- ❌ 可视化 Demo 页面地址（总决赛要求）
- ❌ 云上部署
- ❌ 开源截图（总决赛要求）
- ❌ 完整应用代码

---

## 3. 三档交付物（明确归类）

### 档 A：初赛必做（11-30 前）

| # | 交付物 | 验收标准 |
| --- | --- | --- |
| A1 | 四类负载真实波形数据 | 每类 ≥ 20 段，有元数据记录 |
| A2 | 三分类模型 + 指标 | 混淆矩阵、准确率、误报率，可复现 |
| A3 | 关键代码片段（2–3 段） | 有注释、能讲清设计意图 |
| A4 | 60 秒演示视频 | 本地跑通"识别 → 告警"，断网也行（可选） |
| A5 | 【模板1】Word 定稿 | 五块内容齐全，数字前后一致 |

**这五项之外的一切，初赛都不做。**

### 档 B：初赛通过后再做（2026-12 至 2027-03）

| 项 | 为什么留给决赛 |
| --- | --- |
| 云上部署（RDS/Redis/OBS） | 总决赛要求 Demo 页面地址 |
| 端侧板部署（树莓派/Atlas） | 现场演示更有说服力 |
| 可视化 Demo 页面 | 总决赛硬要求 |
| 开源仓库完善（README/部署文档/许可证） | 总决赛要交开源截图 |
| 继电器与分级处置演示 | 提升"架构完备"评分 |
| 真实场景验证（宿舍/出租屋实测） | 提升"落地进展"评分 |

### 档 C：只作为答辩储备，不投入开发

| 项 | 状态 |
| --- | --- |
| 产品形态三档与单点成本（¥15–30） | ✅ 已有文档，答辩可讲 |
| 分级处置（延时断电/限功率） | ✅ 已有设计，作为"未来工作" |
| 禁用与同意撤回、申诉机制 | ✅ 已有设计，作为"合规设计"加分项 |
| 商业模式与单位经济性 | ✅ 已有分析，写一页 PPT 即可 |

> 档 C 的价值是**答辩时的深度展示**，不是现在的开发任务。**不要为档 C 写一行代码、买一个零件。**

---

## 4. 初赛"不做清单"（贴墙上）

- ❌ 不做继电器控制与断电演示
- ❌ 不做禁用开关、权限矩阵、申诉界面的实现
- ❌ 不做云上部署（RDS/Redis/OBS/告警推送）
- ❌ 不做开发板部署（树莓派/Atlas 全部不买）
- ❌ 不做 Web/小程序前端（用命令行输出 + 录屏即可）
- ❌ 不做产品化设计（外壳、包装、说明书、认证）
- ❌ 不做多用户/多租户/权限体系
- ❌ 不做实时大屏/可视化看板

> 以上任何一项，**等初赛结果出来再议**。

---

## 5. 初赛评分对照：我们的力气该花在哪

| 官方维度（初赛） | 权重 | 靠什么拿分 | 属于哪档 |
| --- | --- | --- | --- |
| 创新性 | 60% | "判断越界"而非"识别电器"的思路 + 端侧离线 + 无电网数据场景 | 档 A（写清楚） |
| 应用价值 | 40% | 真实数据 + 混淆矩阵 + 误报率 + 单点成本测算 | 档 A（做出来） |

**两个维度全部可以由档 A 支撑，不需要档 B/C 的任何东西。**

## 6. 时间再核对

| 时间 | 事情 |
| --- | --- |
| 现在 → 2026-11-30 | **只做档 A 的五项** |
| 2026-12 | 等初赛结果；若通过，启动档 B |
| 2026-12 → 2027-03-26 | 档 B（云部署、端侧、Demo 页面、开源完善、真实场景） |

**结论：初赛阶段只需要"一个笔记本 + 一个 PZEM + 借来的负载"，其余全部不做。**

---

## 7. 一句话备忘

> **我们要证明的是"这套判断方法有效且能测出来"，不是"我们做出了一个能卖的产品"。**
> 前者是比赛，后者是创业。先把比赛赢下来。
