# 10 · 功能禁用与「同意撤回」设计

> 回答的问题：模型装进插座后，用户/管理者想禁用这个功能，怎么禁用？谁能禁？禁了会怎样？
> 结论：**"禁用"必须拆成三件事分开设计**，否则要么违法（不能撤回同意），要么安全功能形同虚设（一键关掉）。

---

## 1. 为什么这不是一个纯技术问题

### 1.1 三层问题必须分开

| 层 | 是什么 | 能否禁用 | 依据 |
| --- | --- | --- | --- |
| **数据与隐私** | 采集、上报用电数据（属个人信息） | **必须能禁，且要便捷** | 《个人信息保护法》关于撤回同意的要求 |
| **安全保护动作** | 识别到危险后的告警与断电 | **默认不可随意禁** | 安全保护性质，类比烟感不可静默失效 |
| **场所管控策略** | 允许功率、时段、禁止负载类型 | 不是插座的功能 | 由场所管理方制定 |

### 1.2 法律依据（方案书需引用，建议核对官方原文）

- 《中华人民共和国个人信息保护法》**第十五条**：基于个人同意处理个人信息的，个人有权撤回同意；个人信息处理者应当提供**便捷的撤回同意的方式**。撤回同意不影响撤回前已进行的处理。
- 《个人信息保护法》**第十七条**：处理前应以显著方式、清晰易懂的语言告知处理目的、方式、种类、保存期限等。
- **实务结论**：产品**不能设计成"完全无法禁用"**；但也**不能设计成"任何人一键永久关闭"**。

> ⚠️ 法律条文请以全国人大官网/官方文本为准，方案书引用前务必核对原文表述。

## 2. 行业参考：智能插座标准怎么看待"开关与安全模式"

我查阅了一份智能插座技术要求（团体标准草案，公开可下载），其中有几条与本题直接相关：

| 标准中的要求 | 对我们的启示 |
| --- | --- |
| 智能插座应内置继电器模块，接收开关控制指令后拉合闸；触点寿命不低于 5×10⁴ 次 | 开关控制是插座的**既有能力**，我们可复用，不需额外发明 |
| 拉闸时默认只输出 1 次信号，在交流电过零点拉闸；拉闸 300 ms 后自动重合闸 | **断电要讲究时序与自动恢复**，不能蛮干 |
| 智能插座**默认未启用安全模式**，采用双模通信在非安全传输条件下通信 | "功能默认关闭"是行业常见现象，所以**开关状态必须显式可见** |
| 参数设置、电量清零、开关控制等操作，必须**先密钥协商与身份认证**通过后才执行 | **控制类操作必须有权限校验与审计**，不能裸奔 |

## 3. 设计原则（四条）

1. **隐私可退，安全不静默**：数据采集可撤回；保护动作不能悄悄失效。
2. **权限分层，不是一把总开关**：管理者、使用者、设备本体，三者权限不同。
3. **动作留痕，可追溯**：谁、何时、何方式、何原因，全部记录。
4. **离线可用**：断网时也能在设备上暂停与复位，不依赖云。

---

## 4. 权限矩阵（按部署场景）

| 部署场景 | 管理者（宿管/房东/安全员） | 使用者（学生/租客/员工） | 设备本体（物理） |
| --- | --- | --- | --- |
| **宿舍** | 启停管控、修改策略、查看审计 | 不可关闭管控；可**申诉**、可撤回数据上报 | 短按暂停上报；长按复位 |
| **出租屋** | 配置策略、查看记录与审计 | 可申诉；可撤回数据上报；可申请本路暂停监测 | 同上 |
| **自家 / 自用** | 即本人，全部权限 | 全部可关（仍留痕） | 同上 |
| **公共区域配电** | 全权限 | 无（非使用者） | 长按复位 |

> 关键约束：**使用者永远不能直接修改"场所策略"**，只能申诉或撤回自己的数据授权。

## 5. 设备状态机

### 5.1 六个状态

| 状态 | 含义 | 指示灯 | 典型触发 |
| --- | --- | --- | --- |
| `LEARNING` 学习期 | 只采集、只学习基线，不告警 | 蓝灯呼吸 | 首次上电（默认 7 天） |
| `ACTIVE` 监控中 | 采集 + 判断 + 告警 + 保护全部开启 | **绿灯常亮** | 学习期结束 |
| `PAUSED` 已暂停 | 停止上报与告警，**仍保留断电保护** | **黄灯慢闪** | 使用者操作 / 管理者临时许可 |
| `DISABLED` 已停用 | 全部智能功能停止，仅基础供电 | **黄灯常亮** | 管理者操作 |
| `FAULT` 故障锁定 | 计量异常、继电器异常、被篡改 | **红灯快闪** | 自动检测 |
| `RETIRED` 已退网 | 设备拆除/替换 | 熄灭 | 管理者 |

### 5.2 状态转换与权限

```
        ┌──────────── 首次上电（默认7天）
        ▼
   [LEARNING] ──学习完成──> [ACTIVE]
        │                     │  ▲
        │                     │  │ 撤销暂停/到期自动恢复
        │                使用者短按│  │
        │                     ▼  │
        │                 [PAUSED] ──超时未确认──> [ACTIVE]
        │                     │
        │              管理者授权│
        │                     ▼
        └───管理者操作────> [DISABLED] ──物理长按/管理员恢复──> [ACTIVE]

   任意状态 ──异常检测──> [FAULT] ──维修/复位──> [ACTIVE]
```

### 5.3 暂停的硬约束

| 约束 | 值 | 原因 |
| --- | --- | --- |
| 使用者单次暂停上限 | 2 小时（可配） | 防长期规避 |
| 暂停期间断电保护 | **保留** | 隐私可退，安全不退 |
| 暂停次数上限 | 每日 3 次（可配） | 防轮番规避 |
| 暂停到期 | **自动恢复 ACTIVE** | 不允许无限期沉默 |
| 暂停是否上报管理者 | **是**（事件级，不含用电内容） | 责任可追溯 |

## 6. 物理与交互设计

| 元素 | 形态 | 作用 |
| --- | --- | --- |
| **物理按键** | 侧面小按键（防误触凹槽） | 短按暂停、长按 5 s 复位；断网可用 |
| **三色指示灯** | 绿/黄/红三色 LED | 让"当前是否被监测"**一眼可见** |
| **蜂鸣器** | 小蜂鸣器 | 告警与倒计时提示 |
| **复位键** | 与电源键复用（长按） | 故障锁定后人工恢复 |

> 设计要点：**状态可见本身就是隐私透明**。我们的卖点不是"悄悄监控"，而是"明确告知 + 可撤回 + 可申诉"。

## 7. 审计与数据最小化

### 7.1 必须记录的事件

| 事件 | 记录字段 |
| --- | --- |
| 状态切换 | 时间、从哪到哪、触发方式（物理/App/管理员）、操作者 ID |
| 暂停 | 时间、时长、理由（可选填）、是否超时自动恢复 |
| 管理操作 | 操作者、操作类型、影响范围、审批单号（如有） |
| 断电动作 | 时间、原因（越界类型）、是否可撤销、恢复方式 |
| 申诉 | 时间、申诉人、判定结果 |

### 7.2 数据最小化原则

- 默认**只上报事件与统计量**（如"某路在 22:10 出现持续充电"），**不上传原始波形**。
- 原始波形仅在：①本地留存（滚动覆盖，如 7 天）；②用户授权后用于模型改进。
- 撤回同意后：停止上报、本地数据按留存策略删除。

## 8. 申诉机制（比禁用更重要）

**为什么必须有**：云南电网公开案例的识别准确率为 88%，即约 12% 可能被误判。没有申诉通道，被误判者会强烈抵触，产品无法持续运行。

### 8.1 流程
1. 告警推送内嵌"这不是违规充电"按钮
2. 用户点击 → 进入申诉队列，**保留供电**（或按策略短暂恢复）
3. 管理者/系统复核（可用端侧记录自证）
4. 复核通过 → 恢复、标记该样本为**误报负样本**，用于模型优化
5. 全过程留痕

### 8.2 一举两得
- 对用户：减少误判伤害
- 对我们：**误报即高质量负样本**，正好解决比赛最缺的数据问题

---

## 9. 需要写进方案书的三句话

1. **"我们把'禁用'分成数据授权、安全保护、场所策略三层，而不是一个开关。"**
2. **"隐私可以撤回，保护不会静默失效——暂停期间断电保护仍然保留。"**
3. **"每一次禁用与恢复都留痕，且设备状态一眼可见，这是透明而不是监控。"**
